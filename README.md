# astrbot_plugin_random_pic

AstrBot 随机抽图插件。图片按两个维度划分：

- **风格**：二次元 / 三次元（Cosplay 与真人写真）
- **分级**：擦边 / R18（R18 仅私聊；可用「内容分级」开关整体关闭）

二次元来自 [Danbooru](#danbooru)（按用户投票分筛选的高分插画）；三次元从 E-Hentai / ExHentai、[哔咔](#哔咔)、[CosplayTele](#cosplaytele) 和 [XiuRen](#xiuren) 中选（默认均分，可手动配置比例）。不带关键词就是在整个池子里完全随机。

一次抽卡抽若干个**图集**，每个图集是同一个画廊 / 帖子 / 本子里的几张图。每个图集第一张图上方有两行标题，后面的图上方只有页码：

```
【2】某某写真
第 15/42 张 · E-Hentai
[图]
第 31/42 张
[图]
作者：…
画廊：https://e-hentai.org/g/…
```

即这次抽卡的第 2 个图集，来自 E-Hentai（来源还有 ExHentai、哔咔、CosplayTele、XiuRen），两张图是该作品 42 张里的第 15、31 张，最后是说明文字。标题行和说明文字都可以关闭。

## 指令

```
/抽图 [风格] [分级] [关键词...] [图集数 或 图集数x每集张数]
/随机角色 [同上]
/pdf [序号]          回复抽到的图片，获取整个作品的 PDF；别名 /全集
/pdf <作品链接>
/抽图 帮助           回复用法说明（任何指令后面跟「帮助」或 help 都可以）
```

| 参数 | 可选值 | 不写时 |
|---|---|---|
| 风格 | `二次元` / `三次元` | `command.default_style`（三次元） |
| 分级 | `擦边` / `r18`（也接受 `R18`、`色图`） | `command.default_rating`（擦边） |
| 数量 | `3`（3 个图集）或 `3x4`（3 个图集、每集 4 张，也可写 `3*4`、`3×4`） | `command.album_count` × `command.images_per_album`（1 × 1） |
| 关键词 | 其余所有词 | 无 |

- 参数顺序随意。总张数不超过 `command.max_images`（默认 5）：超出时先减每集张数，再减图集数。
- 关键词可以直接写中文：标签库能识别的中文名（角色、作品、Coser、属性等）会翻译成 E-Hentai 标签，例如 `芙莉莲` → `character:"frieren$"`、`兔女郎` → `female:"bunny girl$"`；前面加 `-` 表示排除。查不到的词和已经写好的 E-Hentai 语法原样搜索。同一个中文名对应多个标签时（约 600 个，例如 `胡桃`）按 角色 → 作品 → Coser → 属性 → 画师 → 社团 的顺序取第一个，不对时直接写标签，例如 `character:"hu tao$"`。
- 二次元的关键词由 Danbooru 补全成标签（它的 wiki 收录了大量中文、日文名，例如 `芙莉莲` → `frieren`、`原神` → `genshin_impact`、`兔女郎` → `playboy_bunny`），补全不到的中文名再经标签库翻译成英文名补全；最多 2 个关键词（`/随机角色` 时 1 个），`-` 开头的排除词不限个数。二次元一张图就是一个图集，`3x4` 这类写法只取图集数。
- `/随机角色` 的每个图集先随机抽一个角色，再在该角色的作品里抽：每个角色的概率相同，冷门角色也会出现。二次元从 Danbooru 帖子数最多的 2000 个角色里抽（带关键词时从和关键词相关的角色里抽，例如 `/随机角色 二次元 原神`）；三次元从标签库约 9,900 个角色中抽、只用 E-Hentai。没有作品的角色会换一个，每个图集最多换 10 个，所以会慢一些。
- 别名（`command.aliases`）：`/二次元`、`/三次元`（分级用默认值），`/擦边`、`/色图`（风格用默认值），后面同样可以跟参数。
- 群聊里不带 `/`、也不 @ 机器人，直接发 `抽图`、`抽图 原神 2`、`全集` 等也能触发（`command.no_prefix`）。指令词必须在消息开头，后面只能跟空格和参数，「二次元真好」这类普通聊天不会触发。
- 帮助不抽图、不占冷却。没有单独注册 `/help`，因为它是 AstrBot 自带的指令。

示例：

```
/抽图
/抽图 二次元 3
/抽图 原神 2x3
/抽图 二次元 芙莉莲 -兔女郎
/抽图 r18 character:"hu tao$"     （仅私聊，且需开启 R18）
/随机角色 二次元
```

## 图集与发送

- 每个图集独立选图源，从一个作品里抽 `images_per_album` 页，**按页码从小到大**发送；作品页数不够时这个图集少几张。各图集之间的顺序是随机的；没抽够图集数时最后提示「仅获取到 x/y 个图集」。
- `draw.page_pick`：`随机页`（默认）在作品中随机抽页；`从第一页起` 取开头几页（每集 1 张时就是封面）。R18 作品通常从穿着完整开始，随机抽页时跳过开头 `draw.explicit_skip`（默认 30%）。对三次元的所有图源生效（二次元一张图一个图集，不涉及取页）。

`send.mode` 决定怎么发：

| 模式 | 说明 |
|---|---|
| 合并转发（默认） | 一条合并转发消息，**每个图集一个节点**，节点顺序就是序号。只在 QQ / OneBot 可用，其他平台、或只有一个图集时改为图文混合。 |
| 图文混合 | 各图集依次排在一条普通消息里；每条最多 10 张图，更多时分几条发，超过 10 张的图集拆开，后一段重新带上完整标题。 |
| 逐条发送 | 每张图一条消息，都带完整标题；说明文字跟在图集最后一张后面。 |

QQ 拒发（NapCat 发送接口报错，常见于群聊里裸露较多的图）时不再交给 AstrBot 原样重发，而是回复一句「发送失败：QQ 拒发了这条消息」；群聊且关闭了内容分级时提示目前没有内容分级，建议私聊重新抽图。

**并发**：一次抽多个图集时各图源同时抽取，每个图源内部最多同时处理 `network.concurrency`（默认 4）个图集，图集里的几张图也并发下载；其他三次元图源没抽够的图集在它们结束时马上由 E-Hentai 补。Danbooru 的接口请求按每秒约 6 次限速。E-Hentai 的页面请求仍按 `ehentai.request_interval` 限速（不会因为并发更容易被封），省下的是等待网络和下载图片的时间。

## 整本 PDF（/pdf）

回复抽到的图片发送 `/pdf`，插件下载这个图集所在的整个作品并打包成 PDF 发送。所有图源都支持：

| 图源 | 整个作品是 | 链接 |
|---|---|---|
| E-Hentai / ExHentai | 整个画廊 | `https://e-hentai.org/g/123/abcdef0123/` |
| CosplayTele、XiuRen | 整个帖子（一套写真，通常 30~150 张） | `https://cosplaytele.com/hiyuki-2/`、`https://xiuren.biz/xxx/` |
| 哔咔 | 整本，所有话按顺序连起来 | 没有公开链接，只能回复抽图发出的消息 |
| Danbooru | 这个帖子和它的差分（父帖子、子帖子），按发布顺序 | `https://danbooru.donmai.us/posts/123` |

找作品的顺序：

1. 参数里的作品链接，例如 `/pdf https://e-hentai.org/g/123/abcdef0123/`、`/pdf https://cosplaytele.com/hiyuki-2/`。
2. 回复的消息。QQ（OneBot）上插件自己调用发送接口，记下每条发出消息的 ID 和其中的图集（包括图源和作品 id），回复时按消息 ID 直接查（NapCat 发出的合并转发读回来是一张卡片，读不到内容，所以不依赖消息内容）。查不到时（AstrBot 代发、其他平台）解析被回复消息的文字：按 `【序号】` 标题行分段，在说明文字里找作品链接（哔咔没有链接，这种情况下打包不了）。**回复的消息里有多个图集时必须带序号**，即 `【】` 里的数字，例如 `/pdf 2`；不带时插件列出每个图集的序号和标题。
3. 不回复任何消息时，用本会话上一次抽卡（能打包的图集都来自同一个作品时可以不带序号）。

- 分级闸门与抽图相同：E-Hentai 按画廊的分类和标签、哔咔按「無H內容」标签、CosplayTele 按站点分类判定分级，XiuRen 为擦边，无法判定的按 R18 处理；R18 作品只能在私聊打包。命中黑名单、带重口标签、没有标签（E-Hentai、哔咔）或属于站点 AI 分类（CosplayTele、XiuRen）的作品不予打包。
- Danbooru 的差分逐张过滤（黑名单、`danbooru.exclude_tags`、多为儿童设定的角色、动图），过滤掉的不打包；剩下的有任何一张是 q、e 时整组按 R18。没有差分时 PDF 只有这一张图。
- 超过 `pdf.pages_per_file`（默认 200）页时分成多个 PDF 依次发送，文件名标出页码范围，例如 `标题 (1-200).pdf`。E-Hentai 每页都要单独请求、受请求间隔限制，页数越多越慢，也越消耗图片额度；其他图源一次拿到全部图片地址，只花下载时间（实测 110 张的 CosplayTele 帖子约 7 秒）。
- **压缩图片**（`pdf.compress`，默认开启）：每页转成 `pdf.jpeg_quality`（默认 85）质量的 JPEG，PDF 更小；原图是 JPEG 且转换后不会更小时保留原图，透明背景铺白，动图取第一帧。关闭后 JPEG 页面原样放入，其他格式（E-Hentai 现在多是 webp）按质量 95 转成 JPEG，因为 PDF 只能放 JPEG。改了设置后，已经打包的 PDF 不会重新生成。抽图发送的图片始终是原图（实测 E-Hentai 的 webp 转成 JPEG 85 反而大一倍）。
- 打包请求自动排队，不需要重试：不同用户最多同时打包 2 个作品，同一用户的请求依次进行；有人请求的作品正在打包时，等它完成后一起发送。打包 E-Hentai 画廊和抽图共用请求限速，同时打包更多只会互相拖慢。
- 打包过的作品再次请求时直接复用（分卷齐全才复用），最多保留 `pdf.keep_galleries` 个作品的 PDF，只清理本插件生成的文件（文件名是 E-Hentai 画廊号，或 `xiuren_123`、`pica_5f1a…` 这样的「图源_作品 id」）。有页面下载失败时会提示缺了几页，这样的文件不会被复用。
- **QQ 机器人（NapCat 等）和 AstrBot 分属不同容器时，`pdf.output_dir` 必须是两边路径相同的共享目录**（例如两边都挂载为 `/app/sharedFolder` 时填 `/app/sharedFolder/random_pic_pdf`），否则文件发不出去。
- 已发送图集的记录（最近 1000 条消息、每个会话最近一次抽卡）保存在插件数据目录的 `sent_albums.json`，重启后仍可用。

## 定时推送

按固定间隔把一次抽图的结果主动发到指定的群聊或私聊，默认每个整点推送一次。

- **推送会话**（`push.targets`）：在目标群聊或私聊里发送 AstrBot 自带的 `/sid` 获取会话 ID，例如 `aiocqhttp:GroupMessage:123456`，填进列表。列表为空时不推送。
- **推送间隔**（`push.interval_minutes`，默认 60）：从每天 0 点起每隔这么多分钟推送一次，60 为每个整点，30 为每个整点和半点，1440 为每天 0 点；间隔不能整除一天时次日 0 点重新计算。时间按 AstrBot 所在机器的时区。
- **推送内容**（`push.command`，默认 `抽图`）：写法与聊天里的抽图指令相同（不带 `/`），例如 `二次元 3`、`三次元 原神 2x3`、`随机角色`。
- 每个会话单独抽一次，按发送方式发出，同样会登记图集，回复推送的消息也能 `/pdf`。
- 推送不受群白名单、冷却和每日上限限制，但仍受分级闸门约束（例如开启内容分级时 R18 只推送到私聊，群聊擦边需要开启「群聊擦边」）；被拒绝、抽图失败或发送失败时只记日志，不在会话里发消息。

二次元全部来自 Danbooru，没抽够时不由其他图源补。三次元的每个图集从这次能用的图源里选一个：默认均分；开启 `sources.custom_weights`（手动配置比例）后，WebUI 才显示各图源的权重项，按权重分配。某个图源这次不能用时不参与分配，它的份额由其余可用图源分掉。例如只开 E-Hentai、哔咔、CosplayTele 并配置 34 / 33 / 33 时，带 `cosplayer:"xxx$"` 哔咔不能用，E-Hentai 和 CosplayTele（取出标签名 `xxx` 搜索）按 34 : 33 分；`/随机角色` 只有 E-Hentai 能用；R18 时 XiuRen 不参与。能用的图源权重都为 0 时全部从 E-Hentai 抽。关键词命中黑名单或屏蔽的重口标签时，所有图源都直接拒绝（原词和翻译后的标签都检查）。

### Danbooru

[Danbooru](https://danbooru.donmai.us) 是标签最规范的二次元图站（多为 Pixiv、推特上的插画），匿名使用，不需要账号。插件只抽**用户投票分不低于 `danbooru.min_score`（默认 150）**的帖子，一个帖子（一张图）就是一个图集，发原图（超过 `network.max_image_mb` 时发 850px 宽的缩小图）。

- **分级**：Danbooru 的 sensitive 为擦边，questionable 和 explicit 为 R18。2026-10 抽样目检（150 分以上）：擦边 24 张随机图约 20 张明显擦边、其余较轻，全部是完成度高的插画；R18 全部达标（questionable 多为露点，explicit 为性内容）。50~100 分的擦边只有约 16/24，杂图也多，所以默认 150 分；此时擦边池约 7.8 万张、R18 池约 27 万张。带关键词或 `/随机角色` 时按这个分数搜不到，会降到三分之一（50 分）再搜一次。
- **排除**：`danbooru.exclude_tags` 里的标签（默认漫画、多格、黑白、草图、3D、AI 生成和辅助、男同、男性向、兽人），以及视频、动图和 `aged_down`（低龄化版本）始终排除；黑名单、重口标签与其他图源相同（Danbooru 标签的下划线视为空格）。
- **儿童设定的角色**：Danbooru 的 `loli` / `shota` 标签基本只打在性内容上，设定是儿童的角色在擦边图里不会被标出，R18 图里也有漏标。所以插件按角色统计：一个角色的 R18 帖子里带 `loli` / `shota` 的比例达到 20% 时，这个角色的所有帖子都不抽，用它当关键词时直接拒绝（实测可莉 0.88、纳西妲 0.85、伊莉雅 0.56、阿比盖尔 0.31、空崎日奈 0.28；芙莉莲 0.03、约尔 0.02）。统计结果缓存一天。注意这只针对「多被画成儿童」的角色，设定是高中生的角色不受影响。
- **随机原理**：不超过 1 个关键词时用 Danbooru 的 `random:N` 在全部符合条件的帖子里均匀随机取一批候选，各图集共用，约 1 秒一批；2 个关键词时（`random:` 也算一个标签，匿名最多 2 个）改用游标随机：在最旧和最新的帖子 id 之间随机跳一页。游标会偏向老帖子（高分帖子越新越密），所以只在这种情况下用。
- **说明文字**：画师、作品、评分、出处（有 Pixiv 作品号时给 Pixiv 链接）和帖子链接；标题是角色名，标签库有中文名时显示中文。
- 必须用非浏览器的 User-Agent 访问（浏览器 UA 会被 Cloudflare 拦成 403），插件已处理；接口请求限速为每秒约 6 次，短时间请求太多会被 429。

### E-Hentai

E-Hentai 只用于三次元（2026-10 起二次元改用 Danbooru：E-Hentai 的二次元画集多是设定集、线稿和漫画分镜，质量偏低）。


`ehentai.site` 选择 `e-hentai`（表站）或 `exhentai`（里站）。里站需要 cookie `ipb_member_id`、`ipb_pass_hash`、`igneous`（登录 e-hentai.org 后从浏览器复制，`igneous` 在访问 exhentai.org 后获得），缺任意一个时改用表站并在日志中警告；表站填前两个可以提高图片额度。Cookie 只发给当前站点的域名，不会发给图片服务器、GitHub 等第三方；无效时里站返回空白页面，插件会回复「ExHentai cookie 无效或已过期」。

**随机原理**：E-Hentai 没有随机排序，列表页只能用游标翻页（`next=<gid>`）。插件先取搜索结果中最新和最旧画廊的 gid（缓存 1 小时），在范围内随机取一个 gid 跳过去，从那一页（最多 25 个）随机挑几个候选；一轮的候选合并成一次 `gdata` API 请求取得分类和完整标签，逐个复核，通过的画廊里取图。gid 随上传时间递增，所以这是按时间近似均匀的抽样。图片服务器失败时用页面上的 `nl` 参数换一台服务器再试一次。每个图集大约需要 3~4 次请求，默认请求间隔 0.5 秒，抽卡耗时主要受它限制。

**画廊池**（`pools` 段）：擦边、R18 两个池子各自的分类、搜索条件和「必须带其一的标签」（`female:*` 表示该命名空间下任意标签）：

| 擦边 | R18 |
|---|---|
| Cosplay / Asian Porn，带 `non-nude`，排除 `nudity only` | Cosplay，带任一裸露 / 性内容标签 |

为什么这样定：

- E-Hentai 上的真人内容基本只在 Cosplay 和 Asian Porn 两个分类里（Western、Image Set、Non-H 几乎都是绘画，Misc 七成是 3D 渲染），站上没有通用的「真人照片」标签。Asian Porn 的无露点画廊以杂志写真为主，所以加进了擦边池；R18 池不加，因为其中有业余和流出内容，真人年龄也无法靠标签过滤。

全局还有 `ehentai` 段的最低评分（默认 4 星）、排除 AI 生成画廊、最少页数。

### 哔咔

[哔咔漫画](https://www.picacomic.com)（PicACG）的 **Cosplay 分类**（约 9400 本写真），在 `pica` 段填好账号和密码后启用（手动配置比例时哔咔权重还要大于 0）。

- 支持普通关键词（在 Cosplay 分类里搜索，`-` 开头的词在本地按标签、标题、作者排除）。搜不到时由 E-Hentai 补上。
- **分级看「無H內容」标签**：带它的算擦边，不带的算 R18（抽样 30 本约 83% 带这个标签，不带的多是尺度更大的写真），和 E-Hentai 一样受内容分级约束。
- 未成年内容过滤检查标签、标题和作者；标签是繁体中文，所以基线黑名单里有 `蘿莉`。没有标签的本子丢弃。
- 一本是一个图集，从随机的一话里取。哔咔没有公开的网页地址，说明文字只有作者和标签。
- 原理：调用哔咔 App 的接口 `picaapi.picacomic.com`，每个请求按 App 的方式做 HMAC-SHA256 签名。账号密码换 token（有效期约 7 天，过期自动重新登录，登录失败后 10 分钟内不再尝试）。登录接口限流很严，所以 token 保存在插件数据目录的 `pica_token.json`，重载插件后继续使用。

### CosplayTele

[cosplaytele.com](https://cosplaytele.com) 的 Cosplay 写真（约 5600 套，多为中国、东南亚的职业 Coser）。

- **分级看站点分类**：「Cosplay Ero」为擦边，「Cosplay Nude」为 R18，两个分类几乎不重叠，同时在两边的按 R18；排除站点的「AI Art」分类。2026-10 抽样目检：擦边分类 24 张随机页 23 张达到擦边；R18 分类随机单页约 2/3 露点，其余是同一套里还穿着的页（和 E-Hentai 一样按整套定分级，随机抽页时同样跳过开头 `draw.explicit_skip`）。
- 关键词先经标签库翻译，E-Hentai 标签取出标签名再搜索（`芙莉莲` → `frieren`），因为站点的标题和标签是英文角色 / 作品名；`-` 开头的词在本地按标题、分类和标签排除。没有标签库时原样搜索。
- 一个帖子是一个图集，说明文字为标签和帖子链接。未成年内容过滤检查标题、分类和标签。

### XiuRen

[xiuren.biz](https://xiuren.biz) 收录的秀人、尤蜜、语画界等工作室棚拍写真（约 1 万套），**只用于擦边**（2026-10 抽样目检 24 张随机页 21 张达到擦边，没有分级分类，少数套图有手遮胸一类的半裸页）。排除站点的「AI Generated」分类和标签。

- 关键词原样搜索（标题多是中文模特名，例如 `鱼子酱`），不经标签库翻译；E-Hentai 标签写法取出标签名搜索。
- 一个帖子是一个图集，说明文字为标签和帖子链接。

两个站都是 WordPress，插件调用公开的 REST 接口 `/wp-json/wp/v2/posts`：`per_page=1&page=N` 取第 N 个帖子，响应头 `X-WP-Total` 是符合条件的帖子数（缓存 1 小时，带关键词时 10 分钟），所以随机抽一个帖子只要一次请求，图集之间完全并发；正文里的 `<img>` 就是整套图，没有防盗链。站点改版失效时开启手动配置比例、把权重设为 0 即可。

## 内容安全

`access.content_rating`（内容分级，默认开启）控制下面的第 1、2 条：关闭后不再区分分级，群聊和私聊可用的内容相同（R18 仍需 `r18_enabled`），`group_sensitive` 不再生效，抽到的作品只复核风格。第 3、4 条始终生效。

1. **R18 双重闸门**：请求阶段群聊一律拒绝 R18；结果阶段再按作品的实际分级复核，只要是 R18 就必须是私聊。`r18_enabled` 默认关闭；群聊擦边由 `group_sensitive` 控制，默认关闭（关闭时群聊里本插件不可用）。
2. **分级复核**：不管画廊池怎么配置，抽到的 E-Hentai 画廊都按分类和标签重新判定，与请求不符就丢弃重抽：
   - 风格：只要 `Cosplay`、`Asian Porn` 分类（三次元），其他分类丢弃。
   - 带任一裸露 / 性内容标签为 R18：`other:nudity only`、`uncensored`、`mosaic censorship`、`full censorship`、`hardcore`、`no penetration`、`object insertion only`（打码类标签只用于露出性器官的画廊，和 `non-nude` 同时出现时以 R18 为准）；否则带 `other:non-nude` 为擦边；都不满足时无法判定、直接丢弃。
   - 抽样（500 个 Cosplay 画廊）：约 78% 带 `non-nude`，约 20% 带裸露 / 性内容标签，约 2% 两者都没有。
   - 标签是画廊级的：R18 画廊里的随机一页可能还穿着衣服。
   - 其他图源：Danbooru 按帖子分级，哔咔按「無H內容」标签，CosplayTele 按站点分类，XiuRen 全部为擦边，结果阶段同样复核。
3. **未成年内容过滤**：命中黑名单就丢弃重抽，没有标签的作品也丢弃（CosplayTele、XiuRen 是真人写真站，没有可靠的标签，检查标题、简介和站点的分类 / 标签名称）；每次 E-Hentai 搜索还会排除 `lolicon`、`shotacon` 等标签（里站能搜到这类画廊）；Danbooru 另外排除多为儿童设定的角色（见 [Danbooru](#danbooru)）。内置基线黑名单不可删除，只能用 `draw.extra_blacklist` 追加：
   `loli, lolicon, shota, shotacon, toddlercon, child, female_child, male_child, toddler, randoseru, kindergarten uniform, age regression, 萝莉, 蘿莉, 正太, 幼女, 幼児, ロリ, ショタ`
   英文词按整词匹配（`female:lolicon` 命中，`lolita fashion` 不会），中日文词按子串匹配，都忽略大小写。
4. **屏蔽重口**（`draw.block_heavy`，默认开启）：带 `draw.heavy_tags` 中任一标签（E-Hentai 按标签名匹配 `female` / `male` / `mixed` 命名空间，Danbooru 直接按标签名匹配）的作品不会被抽到，也不能打包；关键词本身是这类标签时（如 `抽图 猎奇`，中文先翻译成标签）直接拒绝，不带命名空间的英文词是标题搜索（`blood` 可能在找《Blood+》），不拒绝。默认列表包括猎奇、杀害、截肢、身体改造、吞食、粪便、呕吐、拷打、血液、凌虐、兽交、虫类、尿布等；实测 E-Hentai 二次元 R18 画廊约 9% 带这类标签。

## 配置项

配置分段与 WebUI 面板一致：

| 分段 | 内容 |
|---|---|
| `access` 权限与分级 | 内容分级、R18、群聊擦边、群白名单、用户黑名单、每人冷却、每人每日图片上限 |
| `command` 指令 | 默认风格 / 分级、默认图集数 / 每集张数、单次最多图片数、别名、群聊无前缀触发 |
| `send` 发送 | 发送方式、标题行、说明文字 |
| `push` 定时推送 | 启用、推送间隔、推送会话、推送内容 |
| `draw` 取图与过滤 | 取图位置、R18 跳过开头比例、追加黑名单、屏蔽重口及重口标签 |
| `sources` 三次元图源比例 | 手动配置比例开关；开启后才出现 E-Hentai、哔咔、CosplayTele、XiuRen 的权重 |
| `network` 网络与缓存 | HTTP 代理（所有图源和标签库共用）、请求超时、并发数、单张图片上限、图片缓存上限 |
| `danbooru` 二次元 | 最低评分、排除的标签 |
| `ehentai` 三次元 | 站点、cookie、最低评分、排除 AI、最少页数、请求间隔 |
| `pools` E-Hentai 画廊池 | 三次元擦边、R18 两个池子的分类、搜索条件、必须带其一的标签 |
| `pica` 哔咔账号 | 账号、密码 |
| `tag_db` 标签中文库 | 启用、下载地址 |
| `pdf` 整本 PDF | 启用、单个 PDF 最多页数、存放目录、压缩图片及 JPEG 质量、保留的作品数 |

- 国内通常需要在 `network.proxy` 配置代理。所有请求都有超时，全部失败时回复失败原因，不会没有响应。
- 图片先下载到插件数据目录的 `cache`，再以本地文件原样发送；超出 `network.cache_mb` 时删除最旧的图片，10 分钟内下载的不删。
- 冷却和每日计数（按成功发出的张数）保存在内存中，重启后清零。

## 标签中文库

中文关键词翻译、说明文字中的作品 / 角色中文名和三次元的 `/随机角色` 依赖 [EhTagTranslation 数据库](https://github.com/EhTagTranslation/Database)。插件运行时下载 `db.text.json.gz`（约 1.3 MB）到插件数据目录，每 7 天更新一次；下载失败时沿用旧缓存，10 分钟内不重试。GitHub 无法访问时在 `tag_db.url` 填镜像地址。标签库不可用时关键词原样搜索（Danbooru 仍能补全中文名）、说明文字显示英文标签、三次元的 `/随机角色` 不可用。
