# astrbot_plugin_random_pic

AstrBot 的 E-Hentai / ExHentai 随机抽卡插件。每次随机抽一个画廊，再从里面随机取一页发出来；三次元还可以混入 [16K](#16k三次元图源) 的随机图。图片按两个维度划分：

- **风格**：二次元 / 三次元（Cosplay 与真人写真）
- **分级**：擦边 / R18（R18 仅私聊；可用 `content_rating` 整体关闭分级）

两个维度组合成 4 个画廊池。不带关键词就是在整个池子里完全随机；每张图默认附带画廊标题、作者、作品、角色、分类、页码、评分和画廊链接（`send_caption` 关闭后只发图片）。

## 指令

```
/抽图 [风格] [分级] [关键词...] [数量]
/随机角色 [风格] [分级] [关键词...] [数量]
/抽图 帮助              （或 /抽图 help，回复用法说明）
/pdf [序号]             （回复抽到的图片，获取整个画廊的 PDF；别名 /全集）
/pdf <画廊链接>
```

| 参数 | 可选值 | 默认 |
|---|---|---|
| 风格 | `二次元` / `三次元` | 三次元（`default_style`） |
| 分级 | `擦边` / `r18`（也接受 `R18`、`色图`） | 擦边（`default_rating`） |
| 数量 | 数字 | `default_count`（默认 1），上限 `max_count`（默认 5） |
| 关键词 | 其余所有词 | 无 |

参数顺序随意：先识别风格词和分级词，数字当作数量，其余作为关键词追加到 E-Hentai 搜索条件里。没写风格或分级时使用配置中的默认值（默认三次元·擦边）。

群聊里不带 `/`、也不 @ 机器人，直接发 `抽图`、`抽图 原神 2`、`全集` 等也能触发（`no_prefix_trigger`，默认开启）。指令词必须在消息开头，后面只能跟空格和参数，所以「二次元真好」「我要抽图」这类普通聊天不会触发；别名关闭时别名也不会无前缀触发。AstrBot 的指令默认要求群聊带唤醒前缀，插件额外注册了一个不受前缀限制的正则处理器来实现这一点；带 `/` 时仍走原来的指令，不会重复触发。

第一个参数是 `帮助` 或 `help`（不区分大小写）时，回复用法说明，不抽图、不占冷却。所有指令都支持，例如 `/随机角色 帮助`。没有单独注册 `/help`，因为它是 AstrBot 自带的指令。

关键词可以直接写中文：标签库能识别的中文名（角色、作品、Coser、属性等）会被翻译成 E-Hentai 标签，例如 `芙莉莲` → `character:"frieren$"`、`原神` → `parody:"genshin impact$"`、`兔女郎` → `female:"bunny girl$"`，前面加 `-` 表示排除（`-兔女郎`）。查不到的中文词、英文词和已经写好的 E-Hentai 语法原样搜索。关键词命中黑名单（例如 `萝莉`）时直接拒绝。

同一个中文名对应多个标签时（约 600 个，例如 `胡桃` 既是原神的胡桃也是另一个角色 kurumi），按命名空间顺序（角色 → 作品 → Coser → 属性 → 画师 → 社团）取第一个，结果不一定是你想要的。这时直接写 E-Hentai 标签，例如 `character:"hu tao$"`。

`/随机角色` 的每张图先从标签库约 9,900 个角色中随机抽一个，再在该角色的画廊里抽。和 `/抽图` 的区别是：`/抽图` 每个画廊的概率大致相同，热门作品出现得多；`/随机角色` 每个角色的概率相同，冷门角色也会出现。很多角色在某个池子里没有画廊，每张图最多换 10 个角色，所以会慢一些（实测每张约 3~4 秒）。

示例：

```
/抽图
/抽图 二次元 3
/抽图 原神 2
/抽图 二次元 芙莉莲 -兔女郎
/抽图 r18 character:"hu tao$"     （仅私聊，且需开启 R18）
/随机角色 二次元
/抽图 帮助
```

便捷别名（`enable_aliases` 开关，默认开启），后面同样可以跟参数：

| 别名 | 等同于 |
|---|---|
| `/二次元` | `/抽图 二次元`（分级用默认值） |
| `/三次元` | `/抽图 三次元`（分级用默认值） |
| `/擦边` | `/抽图 擦边`（风格用默认值） |
| `/色图` | `/抽图 r18`（风格用默认值） |

旧版的 `/随机图` 已改名为 `/抽图`。

### 多张图

- 一次抽到多张图时，默认打包成一条**合并转发**消息，每张图（连同说明文字）是一个节点，节点顺序就是抽图顺序（`send_mode` 可改为逐条发送；合并转发只在 QQ / OneBot 平台使用，其他平台自动逐条发送）。
- `same_gallery` 开启后，一次抽卡只选一个画廊，从中随机抽多页，**按页码从小到大**发送；画廊页数不够时少发几张，不会混入别的画廊。R18 同样跳过前 30% 的页。
- 关闭 `send_caption` 后只发图片，不附文字。

### 整本 PDF（/pdf）

回复抽到的图片发送 `/pdf`，插件会下载整个画廊并打包成 PDF 文件发送。找画廊的顺序：

1. 参数里带画廊链接：`/pdf https://e-hentai.org/g/123/abcdef0123/`。
2. 回复的消息：先看文字里的画廊链接（带说明文字时），再按图片的字节数查插件登记的「已发送图片」（纯图片时）。回复合并转发消息时，如果里面有多个画廊，会列出来让你加序号，例如 `/pdf 2`。
3. 不回复任何消息时，用本会话上一次抽卡的画廊（多个画廊同样要加序号）。

说明：

- 分级闸门与抽图相同：按画廊的分类和标签判定分级（无法判定的按 R18 处理），R18 画廊只能在私聊打包；命中黑名单或没有标签的画廊不予打包。
- 画廊页数不设上限：超过 `pdf.pages_per_file`（默认 200）页时分成多个 PDF 依次发送，文件名标出页码范围，例如 `标题 (1-200).pdf`、`标题 (201-450).pdf`。每页都要单独下载，25 页实测约 20 秒；页数越多越慢，也越消耗 E-Hentai 的图片额度。同一时间只打包一个画廊。
- PDF 存放在 `pdf.output_dir`，打包过的画廊再次请求时直接复用（分卷齐全才复用），最多保留 `pdf.keep_files` 个画廊的 PDF，按画廊整体清理，只动本插件生成的文件（文件名以画廊号开头）。有页面下载失败时会提示缺了几页，这样的文件不会被复用。
- **QQ 机器人（NapCat 等）和 AstrBot 分属不同容器时，`pdf.output_dir` 必须是两边路径相同的共享目录**（例如两边都挂载为 `/app/sharedFolder` 时填 `/app/sharedFolder/random_pic_pdf`），否则 NapCat 读不到文件，发不出去。
- 已发送图片登记表保存在插件数据目录的 `sent_images.json`，重启后仍可用。NapCat 回传的图片文件名是临时名，不能用来识别图片，所以按字节数登记。

## 站点与 Cookie

`ehentai.site` 选择 `e-hentai`（表站，默认）或 `exhentai`（里站）。

- 里站需要在 `ehentai` 配置段填写 cookie `ipb_member_id`、`ipb_pass_hash`、`igneous`（登录 e-hentai.org 后在浏览器开发者工具里复制，`igneous` 在访问 exhentai.org 后获得）。缺任意一个时自动改用表站，并在日志中警告。
- 表站也可以填 `ipb_member_id`、`ipb_pass_hash`，登录后图片额度更高。
- Cookie 只发给当前站点的域名（及其子域名），不会发给图片服务器、GitHub 等第三方。
- Cookie 无效时里站会返回空白页面，插件会直接回复“ExHentai cookie 无效或已过期”。
- 登录账号的站点设置会生效，例如画廊每页缩略图数量：插件会根据页面上的「Showing x - y of z」自动校正。
- 里站能搜到萝莉、正太类画廊，所以每次搜索都会排除 `lolicon`、`shotacon`、`low lolicon`、`low shotacon`、`oppai loli`、`toddlercon` 标签；本地黑名单仍然作为第二道过滤。

## 随机抽卡原理

E-Hentai 没有随机排序，列表页也只能用游标翻页（`next=<gid>` 返回 gid 更小的下一页）。插件的做法：

1. 对某个搜索条件，先取第一页得到最新画廊的 gid，再取最后一页（`prev=1`）得到最旧画廊的 gid。这个范围缓存 1 小时。结果只有一页时直接从这一页抽。
2. 在范围内随机取一个 gid 作为游标跳过去，得到一页（最多 25 个）画廊，随机挑几个候选。
3. 一轮的所有候选合并成一次官方 API（`gdata`）请求，取得分类和完整标签，然后逐个复核。
4. 通过复核的画廊里随机取一页（或封面），解析图片地址并下载。R18 画廊通常从穿着完整开始，所以默认跳过前 30% 的页（`ehentai.explicit_skip_ratio`）。图片服务器失败时用页面上的 `nl` 参数换一台服务器再试一次。

gid 随上传时间递增，所以这是按时间近似均匀的抽样。每张图大约需要 4 次请求，默认请求间隔 0.5 秒，一张图通常 4~7 秒。

## 画廊池

| 风格 \ 分级 | 擦边 | R18 |
|---|---|---|
| 二次元 | Non-H，带泳装 / 比基尼 / 内衣 / 兔女郎 / 大胸等擦边属性之一，且是画集或图集（`artbook` / `non-h imageset`） | Artist CG / Game CG / Image Set，必须带人物标签（`female:` / `male:` / `mixed:`），排除 `non-nude` |
| 三次元 | Cosplay / Asian Porn，带 `non-nude`，排除 `nudity only` | Cosplay，带任一裸露 / 性内容标签（见下） |

二次元两个池都排除线稿（`sketch lines`），擦边池还排除裸露和绘画教程。

为什么这样定：抽样 200 个旧版二次元擦边池（纯画集 / 图集）的画廊，78% 不带任何人物标签，多是设定集、线稿和教程，例如机甲动画画集、速写本；无 H 分类本身也不是擦边分类（还有百合漫画、游戏说明书等）。所以改为先按擦边属性搜索，再在本地要求是画集或图集（排除整页文字的漫画）。「必须带其一的标签」可以在 `pools` 配置段修改，`female:*` 表示该命名空间下任意标签。

**二次元只发彩图**（`anime_color_only`，默认开启）：图片下载后检查颜色，黑白页（黑白漫画、线稿、草图）丢弃并换同一画廊的另一页，每个画廊最多多试 4 页。实测黑白页的彩色像素占比为 0，最素淡的彩色画集页也有 17%，阈值取 5%。画廊标签无法保证这一点：标了 `full color` 的画集里也有黑白线稿页。

全局还会加上 `ehentai` 配置段的条件：最低评分（默认 4 星）、排除 AI 生成画廊（默认开启）、最少页数（默认不限）。

为什么三次元按分类区分：抽样统计各分类后，E-Hentai 上的真人内容基本只在 Cosplay 和 Asian Porn 两个分类里（Western、Image Set、Non-H 几乎都是绘画，Misc 七成是 3D 渲染），站上也没有通用的「真人照片」标签。Asian Porn 的无露点画廊以杂志写真为主，所以加进了擦边池；R18 池默认不加 Asian Porn，因为其中有业余和流出内容，真人年龄也无法靠标签过滤。

每个池的分类和搜索条件都可以在 WebUI 的 `pools` 配置段里改。例如想在二次元 R18 里加入同人志，就在 `anime_explicit_categories` 中加上 `Doujinshi`（随机页多为漫画分镜）。

## 16K（三次元图源）

[16k.club](https://16k.club) 是一个三次元图片站（自拍、cosplay、写真，夹杂少量 AI 生成图），服务器端支持随机。插件把它作为三次元的第二个图源：

- **只用于不带关键词的三次元抽图**，擦边和 R18 都会用到（`/随机角色`、带关键词时只用 E-Hentai，因为 16K 不能搜索）。
- 每张图按 `sixteenk.ratio`（默认 50%）的概率从 16K 抽，其余从 E-Hentai 抽，两边的图打乱顺序发送；16K 没抽够的张数由 E-Hentai 补上。`same_gallery` 开启时整次抽卡只用一个图源；抽到 16K 时不受「同一画廊」约束，照常从多个帖子凑够张数（帖子大多只有一张图）。`ratio` 设为 0 即不用 16K。
- **16K 没有标签和分级**，擦边和露点都有。开启内容分级时按 R18 对待：只在私聊且开启 `r18_enabled` 时使用，这时私聊里的三次元擦边也可能抽到露点图；关闭内容分级后群聊也会用到。
- 未成年内容过滤只能看帖子标题和简介（命中黑名单就丢弃），无法像 E-Hentai 那样检查标签。
- 帖子里的视频（mp4）跳过，只发图片；只有视频的帖子直接换下一个。
- 每个帖子随机取一张图。说明文字为帖子标题、第几张（帖子有多张时）和帖子链接。16K 的图片不支持 `/pdf`；回复的合并转发里混有 16K 图片时，`/pdf` 只看其中的 E-Hentai 画廊。
- 接口和图片默认走 `ehentai.proxy`（`sixteenk.use_proxy`）。

原理：站点前端调用一个没有文档的 JSON 接口 `https://16k.club/api.php`。`type=post&id=N` 返回帖子的标题和全部图片，并附带 `rand`——服务器随机挑的另一个帖子 id（同一个 id 每次请求都不一样）。插件沿着 `rand` 走，每个帖子只需要一次请求；第一次抽取时先用 `type=index` 取最新的帖子作为起点。实测（2026-10）：约 2.3 万个帖子，`rand` 覆盖全部 id、没有指向已删除的帖子；图片是 webp，没有防盗链，从最早的帖子到最新的都能下载；连续 30 次请求没有被限流。接口没有文档，站点改版时可能失效，这时把 `ratio` 设为 0 即可。

## 屏蔽重口

`block_heavy`（默认开启）：带重口标签的画廊不会被抽到，也不能用 `/pdf` 打包；关键词本身就是这类标签时（例如 `抽图 猎奇`，中文关键词会先翻译成标签）直接拒绝。不带命名空间的英文词是标题搜索（例如 `blood` 可能在找《Blood+》），不会被拒绝，抽到的画廊照样过滤。

## 安全机制

`content_rating`（内容分级，默认开启）控制下面的第 1、2 条：关闭后不再区分分级，群聊和私聊可用的内容相同（R18 请求仍需 `r18_enabled`），`group_sensitive_enabled` 不再生效，抽到的画廊只复核风格和黑名单，`/pdf` 也不再按分级拒绝。第 3、4 条始终生效。

1. **R18 双重闸门**：请求阶段先判断是否私聊，群聊一律拒绝 R18；结果阶段再按画廊实际分级复核，只要是 R18 就必须是私聊。R18 总开关 `r18_enabled` 默认关闭；群聊擦边由 `group_sensitive_enabled` 单独控制，默认关闭（关闭时群聊里本插件不可用）。
2. **分级复核**：不管池子怎么配置，抽到的画廊都会按分类和标签重新判定：
   - 风格：`Cosplay`、`Asian Porn` 为三次元，其余分类为二次元。
   - 分级：
     - 带任一裸露 / 性内容标签为 R18：`other:nudity only`、`uncensored`、`mosaic censorship`、`full censorship`、`hardcore`、`no penetration`、`object insertion only`。打码类标签只用于露出性器官的画廊，所以和 `non-nude` 同时出现时以 R18 为准。
     - 否则 `Non-H` 分类或带 `other:non-nude` 为擦边。
     - 都不满足时：二次元（H 分类本身就是 R18）为 R18；三次元无法判定，直接丢弃。
   - 判定结果必须与请求完全一致，否则丢弃并重抽。
   - 抽样实测（500 个 Cosplay 画廊）：约 78% 带 `non-nude`，约 20% 带裸露 / 性内容标签，约 2% 两者都没有；另有约 0.5% 同时带 `non-nude` 和打码标签。
   - 标签是画廊级的。R18 画廊里的随机一页可能是还穿着衣服的开头部分；擦边画廊同理不会露出。
3. **未成年内容过滤**：检查画廊的全部标签，命中黑名单就丢弃并重抽；没有标签的画廊也会被丢弃。内置基线黑名单不可删除，只能通过 `extra_blacklist` 追加：
   `loli, lolicon, shota, shotacon, toddlercon, child, female_child, male_child, toddler, randoseru, kindergarten uniform, age regression, 萝莉, 正太, 幼女, 幼児, ロリ, ショタ`
   - `randoseru`（小学生书包）等低龄指向标签：无 H 画廊不会打 `lolicon`，但常带这类标签。
   - 匹配忽略大小写。英文词按整词匹配（`:`、`_`、空格等视为分隔，所以 `female:lolicon` 会命中，`lolita fashion` 不会）；中日文词按子串匹配。
   - 匿名访问 E-Hentai 表站时，`lolicon`、`shotacon` 等内容本来就搜不到（只在里站），黑名单是第二道保险。
4. **访问控制**：群白名单（留空表示所有群可用）、用户黑名单、每人冷却时间和每人每日图片上限（按成功发出的张数计）。黑名单用户和白名单以外的群不会收到任何回复。冷却和每日计数保存在内存中，重启插件后清零。

## 网络与发送

- 默认直连 `e-hentai.org`，国内通常需要在 `ehentai.proxy` 配置代理。页面、API 和图片都走这个代理。
- 所有请求带 `nw=1` Cookie，跳过画廊的内容警告页。
- 两次 E-Hentai 请求之间至少间隔 `ehentai.request_interval` 秒。IP 被临时封禁或图片额度用尽（509）时直接停止并回复原因。
- 图片先下载到插件数据目录的缓存（`data/plugin_data/astrbot_plugin_random_pic/cache`），再以本地文件发送。缓存有文件数和总大小上限，每次下载后自动清理最旧的文件。
- 所有 HTTP 请求都有超时（`request_timeout`）。全部失败时回复失败原因，不会没有响应。

## 标签中文库

中文关键词翻译、说明文字中的作品 / 角色中文名和 `/随机角色` 都依赖 [EhTagTranslation 数据库](https://github.com/EhTagTranslation/Database)。插件运行时从 GitHub Release 下载 `db.text.json.gz`（约 1.3 MB）到插件数据目录，默认每 7 天更新一次；下载失败时沿用旧缓存，10 分钟内不重试。GitHub 无法访问时，可以在 `tag_db.url` 填镜像地址，或让下载走 E-Hentai 代理（`tag_db.use_proxy`，默认开启）。

标签库不可用时：关键词原样搜索，说明文字显示英文标签，`/随机角色` 不可用。

数据库内容由 EhTagTranslation 的编辑者共同所有，按 [CC BY-NC-SA 3.0](https://github.com/EhTagTranslation/Database/blob/master/LICENSE.md) 提供，本插件不附带其数据。
