# 文件架构重构实施计划

**目标：** 保留当前工作区的完整功能与未提交改动，按职责整理文件，降低入口和公共模块的耦合。

**架构：** 根入口只负责 AstrBot 命令注册和生命周期委托；`core/runtime.py` 显式装配服务。配置、命令、服务、来源、下载、消息、存储、策略各有单一目录；来源内区分图片、视频和订阅。

**技术：** Python、AstrBot、aiohttp，沿用现有依赖与数据模型。

参考：`astrbot_plugin_media_parser` 的 `5265ff57bf83caa7f5d6a94e7197d0dbd5f6dbf7`。采用其职责分层和显式装配，不复制其大入口、动态加载或当前项目不需要的功能。

## 约束

- 以现有工作区文件为准，保留未提交配置和订阅改动。
- 保留根 `main.py`、`metadata.yaml`、`_conf_schema.json`、`requirements.txt`。
- 不改变命令、配置字段、权限、分级、抽取算法或运行数据路径。
- 配置迁移仍在插件导入时执行；资源路径不再依赖被移动模块的父目录。
- 直接修改所有内部导入，不留下旧路径转发模块或并行实现。
- 测试仅放根 `test/`，保持 `/test/` 忽略且不跟踪测试。
- 仅运行本次涉及的加载、装配、配置、发送、下载、订阅等定向验证，不运行全量回归。
